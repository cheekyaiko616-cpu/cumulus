# Cumulus

積雲（cumulus）のように、使わなかった日を少しずつ積み重ねる、家計簿と投資のアプリ。
買い物を記録して、使わなかった日を投資資金として貯める。
GitHub Pages でそのまま公開できる（ビルド不要）。記録はこの端末の中（ブラウザ）だけに保存する。

## できること
- 買い物の記録（現金・バーコード決済・クレジット）。レシートの写真から品目と金額を読み取る（写真は保存しない）
- 入力欄：お店・品目・カードの名前・メモ・連携のURLは、長くても折り返して全文が見える（入力すると高さが伸びる）。品目は、品名を全幅、金額を2段目に置く（広い画面では1行）。文字は16pxのまま（iPhoneは16px未満の入力欄で画面が自動で拡大されるため。拡大を避けるには、文字を小さくせず折り返して見せる）。入力欄は、キーボードや下のボタンに隠れない位置まで自動でスクロールする
- カレンダー（1画面）：使った金額、使わなかった日（ブタの貯金箱のイラスト）、カードの引き落とし日（カードのイラスト）
- 投資資金：1日あたりの金額を、使わなかった日ごとに貯める。月ごとに集計（月が替わると0円から。先月以前は一覧に残る）
- 投資の記録：実際に投資した金額。月・全期間・期間指定で、貯まった額／投資した額／残りを見られる
- まとめ：週・月・年・期間指定。支払い方法ごとの内訳（現金・バーコード決済・クレジットはカードごと・カード未選択。金額・件数・割合。押すとその明細）、クレジットの引き落とし。期間の切り替えと上の2つの数字は、スクロールしても動かない（背の低い画面では数字だけ）。投資の画面も同じ。年・複数月の期間指定では、買い物の一覧と内訳の明細を月ごとの帯（その月の合計・件数）に分け、帯は上の固定部分のすぐ下に止まり、次の月の帯に押し出される（CSSの `position: sticky` だけ。スクロールを見張るJS・タイマーなし。固定部分の高さは `--pin-h` で、大きさが変わったときだけ入れる。明細の画面は見出し・合計・閉じるが動かず、明細だけが動く）。週・月・1か月だけの指定は帯なし。内訳は「支払い方法別／お店別」で切り替え：お店別は全体または区分（現金・バーコード決済・各カード・カード未選択）ごとに、上位8店＋その他を横棒で見せる（棒は1位を100%にした長さ。割合の数字も添える）。お店の名寄せは、全角半角・大文字小文字・空白の違いをそろえ、辞書（`RC_CHAINS`・`RC_BRAND_TEXT`）にあるチェーンは支店違いも1つにまとめる。辞書にない店は、そろえた名前が同じときだけまとめる（似た名前は結合しない）。店名が空は「店名なし」。押すとその店の明細。まとめの記録の一覧と明細の行は、1行目に店名と支払額、2行目に「月日・支払い方法・登録方法」だけを出す（品目・メモ・割引・時刻は出さない。日ごとの画面と直す画面で見られる）。月日は、期間が年をまたぐときだけ年を付ける。店名が空は「店名なし」。登録方法は、メール取り込み＝「メール」、メールとレシートを突き合わせ済み＝「メール・レシート」、それ以外＝「手入力・レシート」（レシートの読み取りと手入力は、保存データでは区別できない）
- 拡大しない：ピンチ・ダブルタップの拡大を止める（viewport の `maximum-scale=1, user-scalable=no`、CSS の `touch-action: pan-x pan-y`、iPhone用に `gesturestart` の抑止）。入力欄は16pxのまま。拡大が必要な人には不便になるので、文字は14px以上を基本にしている
- バックアップ：設定の「データ」から、全データを `cumulus-backup-YYYYMMDD.json` に書き出す（スマホは共有シート、使えなければダウンロード）。「バックアップから復元」は、点検に通ったときだけ置き換える（通らなければ何も変えない）。復元の直前の状態は1回分だけ残り、「直前の復元を元に戻す」で戻せる。メール連携のURLと合言葉は含まれない（復元しても、この端末の設定は残る）
- クレジットカード：締め日・引き落とし月・引き落とし日を設定し、いつ・いくら引き落とされるかを表示
- メールから自動取り込み：三井住友カード・JCBカードの「ご利用のお知らせ」メールを取り込む（下記）

## メールからの自動取り込み
あなたのGoogleアカウントの中に小さなプログラム（`tools/apps-script/Code.gs`）を置き、アプリがそのURLに問い合わせる。

- 対応しているカード会社：三井住友カード（送信元 `@vpass.ne.jp`、検索は `from:statement@vpass.ne.jp subject:"ご利用のお知らせ"`）、JCBカード（送信元 `@qa.jcb.co.jp`、検索は `from:mail@qa.jcb.co.jp subject:"ご利用のお知らせ"`）
- 読み取るのは、上の送信元の「ご利用のお知らせ」だけ。アプリに返すのは、日付・時刻・金額・利用先だけ（本文は返さない）
- 合言葉（TOKEN）が合わない呼び出しには何も返さない。合言葉はアプリが作り、「スクリプトをコピー」で自動で入る
- 重複：同じ金額・日付が前後1日以内で、同じカード（またはカード未選択）のクレジットの手入力の記録があれば、記録しない。カード未選択の記録には、メールの発行元のカードを入れる（取り込むとき）。同じ日に同額が2回あれば件数で数え、複数あれば日付が最も近い1件と対応させる
- 記録するときのカードは任意（未選択のまま保存できる。引き落としは「カード未選択」として、月末締め・翌月27日払いで数える）。メールの取り込みや、メール記録と同じ買い物のレシートの登録で、カードが入る
- レシートを後から登録するとき、同じ買い物のメール記録があれば（レシート側がカード未選択でも）、新しく作らずその記録に品目を反映する（「別の買い物」も選べる）
- 日付は、メール本文の「ご利用日時」（利用日）を使う。届く日が遅れても、重複の判定と記録の日付は利用日で行う
- 取消、買物以外（キャッシングなど）は自動では記録しない。JCBは件名に「ショッピング」があるものだけを買物として扱い、それ以外は「要確認」にする
- JCBのメールは「【ご利用日時】【ご利用金額】【ご利用先】」の並びを読む。「▼」から後ろの注意書きは読まない。金額が日本円の整数でないもの（外貨など）は、誤って記録しないよう読み飛ばす（読めなかったメールとして数える）
- 記録するカードは、設定で選べる（選ばないときは、名前に「三井住友」／「JCB」を含むカード。なければ名前だけのカードを作る）
- 取り込んだ目印を残すので、消した記録は再取り込みされない
- 設定の手順は、アプリの「設定 → メールから自動取り込み → 連携の準備」に短く書いてある（更新のしかたは上の「すでに連携している人」の項）
- 三井住友のメールがHTML形式（表・装飾あり）でも読めるよう、プレーンテキストで読めないときはHTML版からタグを除いて読み直す。全角英数・日時と利用先と金額が別の行・「（買物）」の途中改行にも対応する
- アプリのメモに「メール◯通を確認」を出し、検索に合うメールが0通のときは「検索条件に合うメールが0通でした」と出す（スクリプトが found・excluded・checked を返す。通信は増えない）
- すでに連携している人が新しい読み取りを使うには、更新した `Code.gs` を、アプリの「スクリプトをコピー」でコピーし直して貼り替え、デプロイを新しいバージョンにする（「デプロイ」→「デプロイを管理」→ 編集（鉛筆）→ バージョン「新バージョン」→「デプロイ」）。URLは変わらない
- カード会社を足すとき：`Code.gs` の `ISSUERS` に送信元・検索条件・読み取りの関数を足して `python3 tools/make_gas_source.py` を実行し、`js/core/mail-plan.js` の `MAIL_ISSUERS`（名前と、カード名の照合に使う語）と、設定画面（`index.html` と `js/features/mail.js`）の選択欄を足す。保存データの `mail.cards` に同じ id を足す（`js/core/model.js`）

## レシートの読み取り
- 流れ：写真を開く → 暗い背景（黒い布・机）の上なら紙の所だけを切り出す → 長辺3,000px（700万画素）までに縮める → 影に強い白黒にして読む（Tesseract.js 5.1.1・日本語・ひとかたまりの文字として読むPSM 6）→ 文字を整えて解析 → 入力欄に入れる。品目は既存の行の後ろに足し、お店は空のときだけ入れる。支払い方法も入れる（クレジットなら、カードの会社名が名前に入った登録済みのカードが1枚だけのとき、そのカード。分からなければカード未選択）
- 写真を開く：`createImageBitmap`（向きの補正つき）→ 補正なし → `<img>` の順に試す。EXIFの向きが5〜8なのに縦横が保存のままなら、自前で回す（向き1〜4は端末まかせ）。縮小で失敗したら（メモリ不足）、1,800pxでやり直す
- 白黒は影に強い方法（まわりの紙の明るさの85%より暗い所を黒にする。ノイズ・紙の縁の黒い縁取りは除く）。白黒にした画像で文字の高さを測り、48pxより大きければ40pxになるよう縮める（大きすぎる文字は読み違いが増え、時間もかかる）
- 紙の切り出し：縮めた写真の明るさを2つに分け（大津の方法）、いちばん大きな明るい所の外枠を使う。背景がとても暗いか、紙が写真の縁から離れて置かれているときだけ切る（影で暗くなった紙を背景と間違えて切らない）
- 検算と文字の後処理（確信が高いときだけ。確信が低ければ読んだまま。追加の読み取りはしない）：品目の合計が小計・合計（税額を足して合うものを含む）と合わないとき、1品目の金額だけを直して合う直し方が1通りだけなら直す（先頭の1の読み落とし 99→199、1と7・0と8と9・5と6・3と8の取り違え、値引きの名前なのにマイナスが読めない行）。直したときは入力画面の案内に出し、念のため2回目の読み取りもする。品名は、カタカナの中の漢字のような字（口→ロ・力→カ・夕→タ など）とつなぎの記号（-→ー）を文脈で直し、値引き系（クーポン値引・割引など）は同じ字数で1〜2字違いのときだけ直す。品名・店名の辞書による補正は次の項
- 辞書による品名・店名の補正（`js/core/receipt-dict.js`。読み取りのあとの軽い文字列処理だけ。追加の読み取りも通信もしない）：
  - 辞書は2つ。**履歴**＝この端末に保存した記録（`entries` の品名・店名）。読み取りを始めるときに1回だけ表にする（記録が5,000件でも、品名の種類ぶんの表を数十ミリ秒で作る。常駐・タイマー・保存はなし。新しい保存項目もなし）。**内蔵**＝一般的な語（食品・飲料・菓子・日用品・ドラッグストア・約230語）、チェーン名（約90）、市区町村名（約230）。実在の商品名の長い一覧は入れていない（辞書の文字は約7KB）
  - 近さ：似た字（ト/ヒ・ー/-/一・ロ/口・カ/力・ヘ/へ・0/O・1/l・ご/こ・ば/は/ぱ・ッ/ツ・時/里・刈/鐘/釘・鳥/烏 など）のずれを軽く数える編集距離（同じ組0・ゆるい組0.5・それ以外1）で探し、文字2つ組の類似（Dice）も足切りに使う。2つ組の索引で候補を絞るので、履歴が大きくても軽い
  - 許すずれ（辞書の語の字数 n）：2字以下はぴったりのときだけ。3字は似た字のずれだけ（0.4。履歴は0.5）、4〜5字は1、6〜8字は1.5、9字以上は2（履歴は各0.5多く）。似ていない字への取り違いは、かな同士で、5字以上、5〜8字は1つ・9字以上は2つまで。漢字・英数字への取り違いと、字の抜け・余分は、履歴の9字以上の名前で1つだけ。例外：行頭・行末に付きやすい余分な字（ヒ・と・ト・上・ギ・半・羊・洋・学・者・人・`\`・`¥`）と、1つの字が似た2字に割れた余分（「ごこ」「ポボ」）はずれに数えない
  - 直さない（誤補正を避ける）：「おにぎり梅」（履歴に「おにぎり鮭」）・「塩ポテトチップス」（辞書に「ポテトチップス」）のように字が増える・別の字になる名前、同じくらい近い語が2つ以上ある内蔵辞書の候補、辞書にぴったり合う名前、数字を含む名前の近似。履歴どうしで同じくらい近いときは、使った回数の多いほう・新しいほう
  - 品名の前後の飾りは分けて扱う：先頭の英字（D クーポン）、数量・容量（×2・500ml・(小)）、末尾の単価の注記（レジ袋 3円）。数量・容量まで同じ履歴の名前（`full` の表）は、似た字のずれ（0.5まで）だけ直す
  - 店名：店名ぜんたい・チェーン名（店名の前半）・支店名「◯◯店」に分けて直す。支店名が市区町村の一覧か履歴にあれば直さない。支店名だけが読めて、その支店の店が履歴に1種類だけあれば、その店名にする
- 日付の補正：未来・今日から1年以上前の日付、または読めた曜日（`(水)`）と合わない日付は、1桁の読み違い（1と7・0と8・5と6 など）と月・日の先頭の「1」の読み落とし（11月→1月）の候補のうち、実在し（今日から1年以内・翌日まで）、曜日が合う、今日に最も近いものにする。範囲内で曜日だけ合わず候補が複数あるとき、「1月」「1日」と読めて11月・11日のほうが今日に60日以上近いとき以外は、読んだ日付を先頭に残し、候補を並べる。年なしの日付が先の日付で去年にされたときも、今年の1桁違いを探す。直したときは候補（日付のチップ）を出し、2回目の読み取りもする
- 金額の整合：税率ごとの対象額・税額（`8%対象 ¥336 税 ¥26`・`8%対象額`＋`8%税額` の行）を読み、税額が対象額×税率（切り捨て・内税の割り戻し）と合い、対象額の合計が小計と合うときは、その合計（対象額の合計＋税額）を3つめの根拠にする。合計の行・クレジット／お預り−お釣り・小計＋税額・対象額＋税額のうち2つ以上が同じ額で、選んだ合計だけが違うときは、その額にする。品目の合計が合計の1桁違いの読み違い候補のときは、候補（合計のチップ）にも出す（勝手には直さない）
- クーポン・値引き：直前の商品の行のすぐあと（間にバーコードの行・数量の行だけ）に出るマイナスの値引き行は、その商品の価格から引いて1品目にまとめる（チョコ菓子 ¥168 ＋ Dクーポン値引 -50 → チョコ菓子 118）。続く値引きも同じ商品から引く。小計のあと・先頭・全体にかかるもの（お会計・全品・レジ・会員・優待・ポイント利用）・引くと0円以下になるものは、別の行（マイナス）のまま。検算（品目の合計＝小計・合計）はまとめたあとも合う。2回読んだ結果を合わせるときも、まとめた金額と照らし合わせる
- **1回目で、店名・日付・合計・品目のどれかが読めなかったか、品目の合計が合計と合わないときだけ**、写真のまま（白黒にしない）で2回目を読み、足りない項目・品目を補う。電池のため、ふつうは1回で終わる
- 写真は保存せず、外にも送らない。読み取りの部品（本体・wasm・日本語のデータ）だけを jsDelivr から取得する（Tesseract.js が日本語のデータを端末のIndexedDBに残すので、2回目からは取得しない）。取得は時間切れ（部品25秒・データ90秒）つきで1回やり直す。カード番号のような行は、解析の前に読み捨てる
- 失敗の知らせは原因別：写真が開けない／読み取り用のデータを取得できない／時間切れ／文字が読めない／品目が読めない
- 解析：字の間の空白を取り、数字の中の O・l を数字に直し、`¥` が `\`・`Y` に読まれても読む。合計は「合計・台計・合 計・合計(税込)・お会計」や、金額が次の行のもの、見出しが読み違えられたもの（品目の合計と同じ額のときだけ）も拾う。日付は4桁年・2桁年・令和・年なし＋時刻。数量の行（`2個 x 268 536`・`@268 x2`）は品目にせず前の品名に足し、時刻・レジ・登録番号の行は品目にしない。お店は先頭の数行から「店・堂・屋・マート」など店名らしい行を選ぶ。「領収書」「ディスカウントショップ」などの決まった言葉と、記号・同じ字の繰り返し・文字の種類がめまぐるしく変わる並び（読み違い）は使わない。有名なお店の名前（数十件。近い並びも拾う）や本社の所在地の一部から分かれば「お店の名前 支店名」にし、分からなければ「◯◯店」の支店名だけ、それもなければ空にする
- レシートの形を手がかりにする：住所（本社・都道府県＋市区町村・番地）・電話・営業時間・レジ／責No・商品のバーコードの数字（`…JAN`）・小計・対象額・税額・支払い（クレジット・現金・お預り・お釣り・電子マネー・QR）の行は品目にしない。「お買上点数」「売上票」「お客様控え」「カード会社」から下は品目として読まない（カード会社・承認番号などの数字は使わない）。小計より下で品目にするのは値引きだけ
- 合計は「合計」の行 → 支払いの行（クレジット・バーコード決済の額、お預り−お釣り） → 小計＋税額と同じ額の行 → 小計 の順に信じる（小計を合計にしない）。品目の合計と合計の差が税額と同じなら、外税として「消費税」の行を足す。2回読んだときは、片方だけが読めた品目（金額で照らし合わせる）を足して合計が合うなら足す
- いろいろな形式への対応（コンビニ・スーパー・ドラッグストア・飲食店・カフェ・ガソリンスタンド・家電・ホームセンター・100円ショップ・電子レシート・タクシー／鉄道／駐車場・手書き風の領収書・返品・売上票つき・2枚写り・端が切れたもの）：
  - 金額の読み違い：丸数字（⑳②⑥→2026）、`半`・`Y`・`\` → `¥`、`¥1 234`・`¥1.234` → 1,234、`¥1,234-`・`5,500円也`・金額のあとの1〜2文字の写り込み・閉じ括弧。マイナスは `▲100`・`-¥238`・`値引 50-` も読む
  - 合計の見出し：合計・お会計・お買上計・税込合計・現計・総計・ご請求額・ご利用金額・領収金額・領収額・金額（手書き風）。見出しが崩れても、品目の合計と同じ額の行、または「小計・税額・小計＋税額」が並ぶ行を合計の候補にする。税額が税率ごとに分かれているときは、その合計と合計の差が合えば消費税の行にする。品目の合計の1/8にも満たない「合計」（桁の読み落とし）、返品でないのにマイナスの合計は信じない
  - 品目：サービス料・入湯税は品目、ポイント値引・割引・クーポン・優待はマイナスのときだけ値引きの品目、返品／取消のレシートはマイナスの品目と合計を読む。数量の行は、ガソリン（`32.45L x ¥165/L`）・重さ（`348g x 158円/100g`）・`110円 x 2` も前の品名に結び付ける。テーブル・人数・注文番号・入庫／出庫の行は品目にしない。13桁の商品バーコードが品名の前に付いていても品目は残し、4桁ずつ区切られた番号らしい行は数字が欠けても捨てる
  - 日付：`R8.11.11`・`2026.11.11`・`26-11-11`・`11/11/2026`（月/日/年。日/月/年でも読めるときは両方を候補に）・`11月09日 15:20`（年なし）。時刻がなくてもよい
  - お店：「ご利用店舗 〇〇」「発行者 〇〇」の見出し、手書き風の領収書の「領収いたしました」の下の名前、先頭1文字の写り込みの除去。ガソリンの種類・テーブル・合計の行は店名にしない。**合計も日付も読めない崩れた読み取りでは、お店の名前も入れない**（確信が持てない値は空欄にする）
  - 支払い方法：Suica・nanaco・WAONなどの電子マネーは、登録できる3種類のどれでもないので空欄のまま
  - 横向き・上下逆（EXIFなし）の写真：合計も日付も読めないときだけ、90・180・270度回して読み直し、いちばんよい結果を使う（ふつうの写真では回さない）
  - 限界：品名の文字が崩れて名前が読めない行・見出しがすべて崩れた行は、合計の候補（入力欄の上のチップ）と「差額」の行で合わせる。レシートが2枚写っていると、1枚目を読む（2枚目の品目は入れない）。電子マネーの支払い方法は選べない。端が切れて合計の行がないときは、合計は空欄（品目の合計が入力欄に出る）
- 支払い方法：クレジット・売上票・カード会社・VISA／JCB など → クレジット、QR・PayPay・バーコード決済など → バーコード決済、現金・お預り・お釣り → 現金
- 確認：合計と日付の候補が複数あるとき（合計が品目の合計と違うときも）、入力欄の上に候補を出す。押すと日付が入り、合計は「差額」の行で合わせる（同じ額を押すと差額の行は消える）
- 試験：`node tools/test_receipt.js`（483件。解析・辞書補正（架空の履歴・品名）・日付の補正・税率別の整合・向き・白黒化の単体試験。35種類の形式の架空レシート77枚を4通りの読み違いにして、店名・日付・合計・品目数・支払い方法を確かめる）。合成した架空のレシート画像で正解率を測る手順は、同じ画像を Node の `tesseract.js` に通し、店名・日付・合計を比べる（日本語のデータは npm の `@tesseract.js-data/jpn`）
- 採用しなかったこと：**Service Worker によるキャッシュ**（Tesseract.js が日本語のデータをIndexedDBに残すので、重いのは初回だけ。Service Worker を足すと、更新の反映・キャッシュの版管理・起動時の常駐が増え、電池と「ビルド不要」の構成に合わない）、**明るい背景での余白の切り落とし**（机の色や影で、合計の行を切ってしまうおそれがある。暗い背景のときだけ切る）、**日付・金額だけを数字用に別に読み直す**（2回目の読み取りが増え、英語のデータでも数字の読み違いは減らなかった）、**信頼度の低い行だけを切り出して1行として読み直す（PSM 7）**（実レシートの変形9種と合成画像106枚で、1回読みに対し品名の文字正解率が±1ポイント以内で、日付・金額が悪くなる画像もあった。読み直しは信頼度が当てにならない）、**同じ行を縮尺を変えて3通り読んでの多数決**（金額が消えて価格の正解率が下がった）、**傾きの補正**（±3度の写真で、店名は直ったが品名・価格はほぼ変わらず悪くなる写真もあった）、**バーコード（JAN）の検査数字**（検査数字は読み違いの目印になるが、バーコードの行は品目に使わないので、補正には使えない）、**金額欄だけの数字専用の読み直し**（日本語のデータに数字だけの制限をかけても、金額の読み違いは直らず、金額が消える行が増えた。代わりに検算で直す）、**データの種類の変更**（`4.0.0`＝約16MBは読み違いが増え、`best_int`（アプリの既定）が最良。`fast`・`best`は、この環境から取得できず試せなかった）、**ページ分割（PSM 4・3）**（PSM 6より店名・合計が崩れる）、**確信の低い品名の辞書による置き換え**（別の意味の言葉に変えてしまうおそれがある。上の許すずれの範囲だけ直す）、**写真を外部の読み取りサービス（Gemini など）に送る**（写真を外に出さない方針）、**長い商品名の一覧の内蔵**（サイズが増え、新商品に追いつけない。履歴で補う）、**合計の読み違いを品目の合計に合わせて勝手に直す**（品目の読み違いかもしれないので、候補に出すだけ）

## コードの分け方（決まり）
読み込む順番は **core → ui → features → main**。下の層は、上の層を使わない。

| 層 | 置き場所 | 役割 | 決まり |
|---|---|---|---|
| core | `js/core/` | データと計算 | **画面（DOM）に触れない**。保存したあとの画面の更新は、`storage.js` の `onSaved` に `main.js` が入れた処理が行う |
| ui | `js/ui/` | 画面の部品（開閉・選択欄・スワイプ・一覧の行・入力欄） | 業務のルールを持たない。core は使ってよい |
| features | `js/features/` | 画面・機能ごと（1ファイル＝1画面または1機能） | 画面の描画と操作のつなぎだけ。ルールは core に置く |
| main | `js/main.js` | タブの切り替え・見えている画面だけを描く仕組み・起動・画面どうしをつなぐ操作 | 一番上 |

- 各ファイルの先頭に、**役割・依存・実行時・公開** を書く。`依存`＝先に読み込まれている必要があるファイル、`実行時`＝ボタンを押したときなど、実行中にだけ呼ぶファイル、`公開`＝他のファイルから使われる名前
- データの形・上限・初期値・読み込み時の点検は `js/core/model.js` だけに置く（保存データの形を変えるときは、`STATE_VERSION` を上げて `migrate()` で古い形を直す）
- 画面を使わない計算（日付・集計・請求・期間・メールの振り分け・レシートの解析）は core に置き、画面の処理は ui か features に置く
- **`python3 tools/check_structure.py` が、この決まりを検査する**（エラーが0であること）。検査する内容：
  - `js/` の全ファイルが `index.html` に書かれていること（逆も）
  - 先頭の説明があり、`依存` の順番どおりに読み込まれ、使っているファイルが `依存`／`実行時` に書かれていること
  - 下の層が上の層を使っていないこと／core が画面に触れていないこと
  - `公開` の名前が実在し、他のファイルから使われている名前が漏れなく書かれていること
  - 同じ名前を複数のファイルで定義していないこと
  - CSS で使う変数がすべて定義されていること（注意：使われていない class・変数・関数、重複した選択子）
  - 絵文字を使っていないこと（`index.html`・`js/`・`css/`・`Code.gs`。見つけたら「ファイル:行」つきでエラー）
  - `--report` をつけると、ファイル数・行数・重複・未使用の数を出す

## 見た目のルール
- **絵文字は使わない**。印や絵は、`index.html` の先頭にある SVG のスプライト（`<symbol id="i-…">`）に独自のイラストとして描き、`<svg class="…-ic" aria-hidden="true" focusable="false"><use href="#i-…"/></svg>` で置く（使わなかった日 `i-saved`、カード引き落とし `i-card`、投資 `i-up`）
- イラストは、平らな塗り＋深い緑の線だけ（影・グラデーション・動きはなし）。色は `css/base.css` の `--ill-*` の変数だけで決め、明るい設定・暗い設定の両方に値を書く。外部の画像・通信は使わない
- **アプリ内の説明文は最小限**：操作に必要なもの（エラー・警告・カード番号などを入れないでという注意・空の状態の一言）だけを置く。使い方や仕組みの説明は、アプリではなくこの README に書く
- **設定画面は「見出し（一般・カード・メール連携・データ）＋ラベル・値・›の行」の一覧**。詳細は行を押して開く画面で入力する（投資資金のルール `#ruleOverlay`、カード、メール連携）
- 角丸・押せる高さは `css/base.css` の `--r-s/m/l`・`--tap`（44px）を使う。押せる部品は高さ44px以上
- **文字は `css/base.css` のトークンだけで決める**：書体は `--font`（端末の書体を1つ。Webフォントは読み込まない）、大きさは `--fs-xs/s/m/l/xl/2xl/3xl`（11/12/14/16/20/28/36px）、太さは `--fw-regular/medium/bold`、行の高さは `--lh`（文章）・`--lh-ui`（ボタン・一覧）・`--lh-num`（金額・マス）、字間を広げるのはアプリ名だけ（`--ls-wide`）。役割：見出し・入力・ボタン=l、本文=m、補足・ラベル=s、大きな金額=2xl（投資の画面のいちばん大きな数字=3xl）。金額・日付の数字は `font-variant-numeric: tabular-nums` で桁をそろえる。ボタン・入力欄・選択欄・textarea は `font: inherit`。CSSに文字の大きさをpxで直接書かない
- ✓ ✕ ‹ › ▼ ＋ ・ ¥ 〜 のような文字の記号は絵文字ではないので使ってよい。検査は `tools/check_structure.py`

## 保存データの形
ブラウザの `localStorage`（キー `tameru-calendar-v1`。アプリ名を変えても変えない）に、JSONで1つ保存する。読み込むときは `model.js` の `normalize()` が点検し、壊れた項目は捨てる（知らない項目も保存されない）。

| 項目 | 内容 | 型 | 書くところ |
|---|---|---|---|
| `v` | 保存データの版 | 数 | model.js |
| `daily` | 使わなかった日1日あたりの投資資金（円） | 数（0〜1,000,000） | features/settings.js |
| `start` | 数え始める日 | `"YYYY-MM-DD"` | features/settings.js、core/sample.js |
| `sample` | 見本のデータか | 真偽 | core/sample.js |
| `cards[]` | カード：`name` 名前、`close` 締め日（0=月末）、`pay` 引き落とし日（0=月末）、`months` 引き落とし月（1=翌月・2=翌々月） | 配列（30件まで） | features/cards.js、core/mail-plan.js |
| `entries[]` | 買い物：`id`、`date`、`store`、`pay`（cash／code／credit）、`card`、`items[{n,p}]`、`total`、`src`（`"mail"`＝メール由来）、`rc`（レシートと結び付いたか） | 配列 | features/edit.js、core/mail-plan.js |
| `invests[]` | 投資：`id`、`date`、`amount`、`memo` | 配列 | features/invest.js |
| `mail` | メール連携：`url`、`token`（合言葉）、`auto`、`cards.smbc`（記録先のカード名）、`last`（前回の確認の時刻）、`lastNote`、`seen[]`（取り込み済みの目印。1,500件まで） | 辞書 | features/mail.js、core/mail-plan.js |

バックアップのファイルは `{app:"cumulus", v:保存データの版, at:書き出した日時, data:上の形のデータ全体}`。`mail.url`・`mail.token` は入れない。復元は `core/backup-file.js` が、版・大きさ（4MBまで）・型・件数・長い数字（`guard.js`。`id` と `seen` は除く）・`__proto__` などのキーを点検し、`normalize()` を通して、1件も捨てられていないときだけ使う。

保存領域に、記録とは別の小さなキーが2つある（記録の形は変えない）：`tameru-calendar-v1-prev`（復元の直前のデータ1回分。「元に戻す」用。復元・すべて消すで入れ替わる／消える）、`tameru-calendar-v1-bk`（バックアップを最後に書き出した日時。表示用）。

## 電池への配慮（すべてのコードに適用する決まり）
- 定期的に動くタイマーを置かない。日付が変わったときの更新は、次の0時に1回だけ動くタイマー（画面が見えていない間は止める）
- 見えていない画面は描かない（開いたときに描く）。記録が変わっていない更新では、画面を描き直さない
- 通信は、アプリを開いたとき・戻ったときだけ。30分以内は調べず、失敗したあとは10分あけ、設定の誤りは直るまで自動では繰り返さない。オフライン時・データ節約中は通信しない
- 指の動きの処理は、スクロールを止めない設定（passive）にする。動かすのは transform と opacity だけ
- 画像の読み取りは、画像を小さくしてから行い、終わったら作業用の部品と画像をすぐ解放する。進み具合の表示は5%ごと
- 保存は、変更があったときだけ。起動時に書き込まない（初回の確認を除く）
- 外部の読み込みはなし（書体は端末のものを使う）
- 画面の動きは短く、「動きを減らす」設定のときは止める。ダークモードに対応（有機ELの電池を節約）
